# Feature Specification: IELTS Reading Section Simulator

**Feature Branch**: `001-ielts-reading-simulator`
**Created**: 2026-03-10
**Status**: Draft
**Input**: Симулятор IELTS Reading секции — лид-магнит с кастомизируемыми вопросами и брендингом, интерфейс максимально приближен к официальному компьютерному тесту IELTS (Inspera platform). Первая секция проекта, дальше масштабируется на Listening, Writing, Speaking.

## Clarifications

### Session 2026-03-10

- Q: Какой уровень детализации на экране результатов? → A: Полный review — correct/incorrect по каждому вопросу + показ правильных ответов + выделение релевантного фрагмента в тексте пассажа + объяснение почему этот ответ правильный
- Q: Как валидировать текстовые ответы (Sentence/Summary Completion)? → A: Case-insensitive + trim пробелов, опечатки не допускаются (строгое совпадение после нормализации)
- Q: На каком языке интерфейс вне тестовой части? → A: Тест, инструкции и экран результатов (band score, breakdown) на английском; объяснения ошибок и CTA-блок на русском
- Q: Формат конфигурации контента теста? → A: JSON/YAML файл в репозитории проекта — редактируется вручную, применяется при деплое
- Q: UI Reference (agent-browser исследование demo-ielts.inspera.com) → A: Детальный UI reference задокументирован ниже на основе прямого исследования официального демо-теста

### Session 2026-03-10 (Dual Review)

- Q: Как обрабатывать альтернативные правильные ответы для text inputs? → A: Отдельное поле `acceptableAnswers: string[]` на уровне Question; `correctAnswer` — основной ответ, `acceptableAnswers` — допустимые альтернативы
- Q: QuestionGroup.options только для Matching Headings? → A: Для всех matching-типов (Headings, Information, Features, Sentence Endings) — структура `{id, text}` универсальна
- Q: Формат хранения reviewFlags? → A: `string[]` везде (runtime и localStorage), не Set
- Q: Source of truth для таймера при sleep/wake? → A: `startedAt` — source of truth; remaining пересчитывается как `duration - (now - startedAt)`
- Q: Кнопка Retake на экране результатов? → A: Да, secondary стиль; CTA остаётся визуально акцентным (primary)
- Q: Что при наличии незавершённой сессии? → A: Показать экран "Resume / Start New" с явным выбором
- Q: Confirmation dialog перед submit? → A: Да, с указанием количества неотвеченных вопросов
- Q: Пауза таймера? → A: Нет, как в реальном IELTS — только start, без pause
- Q: Runtime validation JSON конфига? → A: TypeScript на билде + минимальная runtime проверка required fields
- Q: Band score при < 40 вопросах? → A: Пропорциональная нормализация: `round(rawCorrect / totalQuestions * 40)`, затем стандартная таблица

## UI Reference (Inspera IELTS Demo)

Источник: прямое исследование https://demo-ielts.inspera.com через agent-browser. Скриншоты сохранены в `specs/001-ielts-reading-simulator/screenshots/`.

### Layout Structure

**Header** (фиксированный, полная ширина):
- Чёрный фон
- Логотип (красный) — слева
- "Test taker ID" текст — рядом с логотипом
- Справа: иконка WiFi/соединения, иконка уведомлений (колокольчик), гамбургер-меню (≡)

**Instruction bar** (под хедером):
- Светло-серый/голубой фон с акцентной левой границей
- "Part X" жирным шрифтом
- Текст инструкции: "Read the text and answer questions X–Y."

**Content area** (split-screen):
- **Левая панель**: текст пассажа — заголовок жирным (крупный), параграфы стандартным шрифтом; для Matching Headings в тексте отображаются пунктирные синие контуры (dashed blue outline) с номером вопроса внутри, куда помещается заголовок
- **Draggable divider**: иконка ↔ по центру между панелями
- **Правая панель**: вопросы — заголовок группы "Questions X–Y", инструкция с выделенными ключевыми словами (bold), интерактивные элементы для ответов; вопросы скроллятся вертикально

**Navigation bar** (фиксированный, нижняя часть):
- Табы частей: "Part 1", "Part 2", "Part 3" с прогрессом "X of Y questions attempted"
- Кнопки номеров вопросов внутри активной части — индивидуальные (1, 2, 3) или сгруппированные (18–19, 20–21, 22–23)
- Активный вопрос выделен рамкой
- Статусы: "Not attempted" (по умолчанию), "Active" (текущий)
- Кнопки Previous (←) и Next (→) — тёмные, справа внизу
- Кнопка "Review your answers" (✓) — справа внизу

### Question Types (наблюдаемые в демо)

1. **True/False/Not Given** — номер вопроса в квадратной рамке, текст утверждения, три radio buttons (TRUE / FALSE / NOT GIVEN). Несколько вопросов видны одновременно с прокруткой.

2. **Note Completion** — инструкция "Complete the notes. Write ONE WORD ONLY from the text for each answer." Формат: маркированный список (bullets), текст с inline text inputs; внутри каждого input отображается номер вопроса (7, 8, 9...).

3. **Summary Completion** — инструкция "Complete the summary. Write ONE WORD ONLY / NO MORE THAN TWO WORDS from the text for each answer." Формат: связный абзац с inline text inputs; номер вопроса внутри input. Лимит слов варьируется по группе вопросов.

4. **Matching Headings** — на стороне пассажа: пунктирные синие рамки (dashed blue outline) с номером вопроса; на стороне вопросов: "List of Headings" — список заголовков в обрамлённых блоках (bordered boxes), которые нужно поместить в соответствующий gap. Кнопка "Help" (keyboard icon) появляется для этого типа.

5. **Multiple Choice — Choose ONE** — radio buttons, один вариант из нескольких.

6. **Multiple Choice — Choose TWO** — checkboxes (не radio buttons), сгруппированные номера вопросов (18–19, 20–21). Пять вариантов на группу, нужно выбрать два.

### Options Menu (гамбургер ≡)

- "Go to submission page" — красная кнопка
- "Contrast" — переключение контрастности (accessibility)
- "Text size" — настройка размера текста (accessibility)

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Прохождение Reading теста (Priority: P1)

Пользователь заходит на страницу симулятора по прямой ссылке и проходит полноценный IELTS Academic Reading тест: 3 пассажа, 40 вопросов, 60-минутный таймер. Интерфейс воспроизводит опыт официального компьютерного теста — split-screen (текст слева, вопросы справа), навигация между вопросами, таймер обратного отсчёта в хедере.

**Why this priority**: Это core value proposition — без рабочего теста остальные фичи бессмысленны. Пользователь должен получить реалистичный опыт прохождения IELTS Reading.

**Independent Test**: Открыть симулятор, пройти все 3 пассажа с вопросами за отведённое время, убедиться что интерфейс соответствует формату официального теста.

**Acceptance Scenarios**:

1. **Given** пользователь открыл ссылку на симулятор, **When** страница загрузилась, **Then** отображается экран приветствия/инструкции с кнопкой начала теста
2. **Given** пользователь нажал «Start Test», **When** тест начался, **Then** отображается split-screen: текст пассажа слева, вопросы справа, таймер 60:00 в хедере начинает обратный отсчёт
3. **Given** пользователь находится на вопросе, **When** он выбирает/вводит ответ, **Then** ответ сохраняется и вопрос помечается как отвеченный в навигации
4. **Given** пользователь ответил на все вопросы или время вышло, **When** он нажимает «Submit» или таймер достиг 0:00, **Then** тест завершается и пользователь переходит на экран результатов

---

### User Story 2 — Навигация внутри теста (Priority: P1)

Пользователь свободно перемещается между вопросами и пассажами внутри Reading секции — так же, как в реальном компьютерном тесте IELTS. Можно вернуться к предыдущему вопросу, перейти к любому пассажу, пометить вопрос для повторного просмотра.

**Why this priority**: Навигация — неотъемлемая часть тестового опыта, без неё симулятор не будет реалистичным.

**Independent Test**: Начать тест, перейти к разным вопросам через панель навигации, пометить вопросы для review, вернуться к помеченным.

**Acceptance Scenarios**:

1. **Given** пользователь находится внутри теста, **When** он нажимает на номер вопроса в панели навигации, **Then** происходит переход к выбранному вопросу с соответствующим пассажем
2. **Given** пользователь на вопросе, **When** он нажимает кнопку «Review» (флажок), **Then** вопрос помечается в навигации визуально отличающимся маркером
3. **Given** пользователь завершил все вопросы, **When** он открывает обзор (Review screen), **Then** видит список всех вопросов с отметками: отвечен / не отвечен / помечен для review
4. **Given** пользователь использует кнопки «Previous» / «Next», **When** он нажимает их, **Then** происходит последовательный переход между вопросами

---

### User Story 3 — Отображение результатов и переход в воронку (Priority: P2)

После завершения теста пользователь видит свой примерный балл (band score) и разбивку по пассажам. На экране результатов присутствует CTA (call-to-action) для перехода на следующий этап воронки продаж.

**Why this priority**: Результаты замыкают пользовательский опыт и конвертируют трафик в лиды через CTA.

**Independent Test**: Завершить тест, увидеть band score и breakdown, нажать CTA-кнопку и убедиться в переходе на целевую страницу.

**Acceptance Scenarios**:

1. **Given** тест завершён (submit или timeout), **When** экран результатов загружен, **Then** пользователь видит: общий band score, количество правильных ответов из 40, разбивку по каждому пассажу, а также полный review всех вопросов с пометками correct/incorrect, показом правильного ответа, выделением релевантного фрагмента в тексте пассажа и объяснением почему ответ правильный
2. **Given** пользователь на экране результатов, **When** он видит CTA-блок, **Then** CTA содержит настраиваемый текст и ссылку перехода на следующий этап воронки
3. **Given** пользователь нажал CTA, **When** происходит переход, **Then** пользователь попадает на настроенную целевую страницу (URL задаётся в конфигурации)

---

### User Story 4 — Кастомизация контента (Priority: P2)

Администратор (владелец симулятора) подставляет свои собственные тексты и вопросы в тест, чтобы не использовать официальные материалы IELTS. Вопросы задаются в структурированном формате.

**Why this priority**: Юридическая чистота — ключевое требование. Без возможности кастомизации контента продукт нельзя использовать публично.

**Independent Test**: Подготовить набор пассажей и вопросов в заданном формате, загрузить в симулятор, пройти тест и убедиться что отображается кастомный контент.

**Acceptance Scenarios**:

1. **Given** администратор подготовил контент в заданном формате (пассажи + вопросы), **When** он размещает контент в конфигурации, **Then** симулятор отображает этот контент при прохождении теста
2. **Given** контент содержит разные типы вопросов (multiple choice, True/False/Not Given, fill-in-the-blank, matching headings), **When** тест запущен, **Then** каждый тип вопроса отображается с соответствующим интерактивным элементом (radio buttons, text input, dropdown и т.д.)
3. **Given** администратор указал правильные ответы в конфигурации, **When** пользователь завершает тест, **Then** система автоматически проверяет ответы и считает балл

---

### User Story 5 — Кастомизация брендинга (Priority: P3)

Администратор настраивает брендинг в хедере симулятора: логотип, название, цветовую схему — чтобы использовать симулятор как брендированный лид-магнит.

**Why this priority**: Брендинг важен для маркетинга, но функционально не блокирует работу симулятора.

**Independent Test**: Изменить настройки брендинга (логотип, текст, цвета), открыть симулятор и убедиться что изменения отражены в хедере.

**Acceptance Scenarios**:

1. **Given** администратор задал логотип и название в конфигурации, **When** пользователь открывает симулятор, **Then** в хедере отображается кастомный логотип и название вместо дефолтных
2. **Given** администратор задал цветовую схему, **When** симулятор загружен, **Then** хедер и акцентные элементы используют указанные цвета

---

### Edge Cases

- Что происходит когда время вышло, а пользователь не нажал Submit? — Тест автоматически завершается, неотвеченные вопросы считаются неправильными
- Что если пользователь случайно закрыл/обновил страницу? — При повторном открытии показывается экран "Resume / Start New"; при resume прогресс восстанавливается, таймер пересчитывается от startedAt (время в sleep учитывается, как в реальном IELTS)
- Что если в конфигурации указано менее 3 пассажей или менее 40 вопросов? — Симулятор работает с тем количеством, которое задано; band score нормализуется пропорционально: `round(rawCorrect / totalQuestions * 40)`, затем стандартная таблица
- Что если текст пассажа очень длинный? — Панель текста скроллится независимо от панели вопросов
- Что если пользователь открывает симулятор с мобильного устройства? — Интерфейс адаптируется: split-screen переключается на вертикальный стек (текст сверху, вопросы снизу) с возможностью переключения между панелями

## Requirements *(mandatory)*

### Functional Requirements

**Тестовый процесс:**

- **FR-001**: Система MUST отображать стартовый экран с инструкциями перед началом теста
- **FR-002**: Система MUST запускать обратный отсчёт 60 минут при старте теста (таймер отображается в хедере)
- **FR-003**: Система MUST отображать split-screen layout: текст пассажа в левой панели, вопросы в правой панели. Над вопросами — instruction bar с индикатором текущей части ("Part X") и текстовой инструкцией ("Read the text and answer questions X–Y.")
- **FR-004**: Система MUST позволять изменять размер панелей (draggable divider с иконкой ↔ между левой и правой частями)
- **FR-005**: Система MUST поддерживать независимый скролл каждой панели
- **FR-006**: Система MUST автоматически завершать тест по истечении времени
- **FR-006a**: Система MUST предоставлять меню настроек (Options) с доступом к: submission page, переключением контрастности и настройкой размера текста
- **FR-006b**: Система MUST показывать confirmation dialog перед финальной отправкой теста с указанием количества неотвеченных вопросов ("Are you sure? X questions unanswered.")

**Типы вопросов:**

- **FR-007**: Система MUST поддерживать тип вопроса «Multiple Choice — Choose ONE» (radio buttons, один вариант из нескольких)
- **FR-007a**: Система MUST поддерживать тип вопроса «Multiple Choice — Choose TWO/THREE» (checkboxes, сгруппированные номера вопросов, например 18–19; нужно выбрать указанное количество вариантов)
- **FR-008**: Система MUST поддерживать тип вопроса «True / False / Not Given» (номер вопроса в квадратной рамке, текст утверждения, три radio buttons)
- **FR-009**: Система MUST поддерживать тип вопроса «Yes / No / Not Given» (аналогично TFNG, но с вариантами YES / NO / NOT GIVEN)
- **FR-010**: Система MUST поддерживать тип вопроса «Matching Headings» — на стороне пассажа пунктирные синие рамки с номером вопроса (drop zone), на стороне вопросов список заголовков в обрамлённых блоках (draggable/clickable); кнопка Help для объяснения механизма взаимодействия
- **FR-011**: Система MUST поддерживать тип вопроса «Note Completion» — маркированный список с inline text inputs; внутри input отображается номер вопроса; инструкция указывает лимит слов (например, "ONE WORD ONLY")
- **FR-012**: Система MUST поддерживать тип вопроса «Summary Completion» — связный абзац с inline text inputs; номер вопроса внутри input; лимит слов задаётся в конфигурации per question group (например, "ONE WORD ONLY" или "NO MORE THAN TWO WORDS")
- **FR-013**: Система MUST поддерживать тип вопроса «Matching Information» (сопоставление информации с параграфами). Каждый вопрос содержит текст утверждения и dropdown-меню с вариантами параграфов (A, B, C...) из questionGroup.options. Пользователь выбирает параграф, содержащий указанную информацию
- **FR-014**: Система MUST поддерживать тип вопроса «Matching Features» (сопоставление утверждений с людьми/категориями). Каждый вопрос содержит текст утверждения и dropdown-меню с именами/категориями из questionGroup.options. Пользователь сопоставляет утверждение с правильной категорией
- **FR-015**: Система MUST поддерживать тип вопроса «Matching Sentence Endings» (сопоставление начал и концов предложений). Каждый вопрос содержит начало предложения и dropdown-меню с вариантами окончаний из questionGroup.options. Пользователь выбирает правильное окончание

**Навигация:**

- **FR-016**: Система MUST отображать фиксированную нижнюю панель навигации с табами частей ("Part 1", "Part 2", "Part 3") и прогрессом "X of Y" для каждой части. Внутри активной части — кнопки номеров вопросов (индивидуальные или сгруппированные, например "18–19")
- **FR-017**: Система MUST визуально различать в навигации статусы вопросов: not attempted (по умолчанию), active (текущий, выделен рамкой), attempted (отвечен)
- **FR-018**: Система MUST позволять переход к любому вопросу по клику на его номер и переключение между частями по клику на таб части
- **FR-019**: Система MUST предоставлять кнопки «Previous» и «Next» (тёмные, справа внизу) для последовательной навигации; Previous disabled на первом вопросе
- **FR-020**: Система MUST предоставлять кнопку «Review your answers» (✓) и экран обзора перед финальной отправкой

**Результаты:**

- **FR-021**: Система MUST автоматически проверять ответы по заданным правильным ответам. Для текстовых ответов (Sentence Completion, Summary Completion) применяется case-insensitive сравнение с trim пробелов; опечатки не допускаются — совпадение должно быть точным после нормализации
- **FR-022**: Система MUST конвертировать количество правильных ответов в IELTS band score (шкала 1-9 с шагом 0.5)
- **FR-023**: Система MUST отображать разбивку результатов по каждому пассажу
- **FR-024**: Система MUST отображать настраиваемый CTA-блок на экране результатов
- **FR-025a**: Система MUST на экране результатов показывать по каждому вопросу: ответ пользователя, правильный ответ, статус (correct/incorrect), выделение релевантного фрагмента в тексте пассажа и текстовое объяснение правильного ответа (объяснения — на русском языке)
- **FR-025b**: Система MUST предоставлять кнопку "Retake Test" на экране результатов (secondary стиль), CTA-блок визуально акцентный (primary). Retake очищает сессию и возвращает на WelcomeScreen

**Кастомизация:**

- **FR-025**: Система MUST позволять задавать контент теста (пассажи, вопросы, правильные ответы, объяснения, ссылки на фрагменты пассажа) через JSON/YAML файл в репозитории проекта. Администратор редактирует файл вручную, изменения применяются при деплое
- **FR-026**: Система MUST позволять настраивать брендинг хедера: логотип, название, цвета
- **FR-027**: Система MUST позволять настраивать CTA-блок: текст, ссылка, стиль кнопки

**Хостинг и доступность:**

- **FR-028**: Система MUST быть доступна по прямой URL-ссылке без регистрации и авторизации
- **FR-028a**: Система MUST при наличии незавершённой сессии в localStorage показывать экран выбора "Resume Test" / "Start New Test" вместо WelcomeScreen
- **FR-029**: Система MUST корректно работать на десктопных браузерах (Chrome, Firefox, Safari, Edge)
- **FR-030**: Система MUST адаптировать layout для мобильных устройств

### Key Entities

- **Тест (Test)**: Контейнер всего экзамена — содержит метаданные (название, время, настройки брендинга, CTA-конфигурация) и список пассажей
- **Пассаж (Passage)**: Текстовый блок для чтения — содержит заголовок, тело текста (с возможностью форматирования: параграфы, подзаголовки, таблицы, изображения) и привязанную группу вопросов
- **Группа вопросов (Question Group)**: Логическая группировка вопросов одного типа внутри пассажа — содержит заголовок ("Questions X–Y"), инструкцию (с ключевыми словами bold), тип вопроса, лимит слов для текстовых ответов (если применимо, например "ONE WORD ONLY" или "NO MORE THAN TWO WORDS"), список вопросов, список опций для matching-типов (headings, paragraphs, categories, sentence endings) — если применимо. В навигации номера могут быть индивидуальными или сгруппированными (например, "18–19" для Choose TWO)
- **Вопрос (Question)**: Единица тестирования — содержит порядковый номер, текст вопроса, варианты ответов (если применимо), правильный ответ, ссылку на релевантный фрагмент пассажа (для выделения при review) и текстовое объяснение правильного ответа. Тип наследуется от Question Group
- **Ответ пользователя (User Answer)**: Выбранный или введённый пользователем ответ на конкретный вопрос в рамках сессии
- **Сессия (Session)**: Состояние прохождения теста — содержит ответы пользователя, оставшееся время, статус (в процессе / завершён)
- **Результат (Result)**: Итог прохождения — количество правильных ответов, band score, разбивка по пассажам
- **Брендинг (Branding Config)**: Настройки оформления — логотип (URL изображения), название, основной цвет, CTA текст и ссылка

## Assumptions

- Целевая аудитория — русскоязычные студенты, готовящиеся к IELTS. Языковая модель: тест (пассажи, вопросы), инструкции перед тестом и экран результатов (band score, breakdown) — на английском; объяснения ошибок при review и CTA-блок — на русском
- Контент (пассажи и вопросы) создаётся и поддерживается администратором вручную через JSON/YAML файл в репозитории; автоматическая генерация и admin-панель не входят в scope
- Оценка Reading band score происходит по стандартной конверсионной таблице IELTS (raw score → band)
- Симулятор stateless для пользователя — нет аккаунтов, истории прохождений, аналитики (MVP)
- Сессия хранится только на стороне клиента (browser); серверное хранение не требуется для MVP
- CTA ведёт на внешнюю страницу (например, Telegram бот, лендинг курса, страница оплаты)
- Один конфигурационный набор контента на один экземпляр симулятора (не мультитест)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователь может пройти полный Reading тест (3 пассажа, 40 вопросов) от старта до получения результатов за одну сессию
- **SC-002**: Все 40 вопросов доступны через навигацию (part tabs + question numbers + prev/next); ни один ответ не теряется при переключении между вопросами и частями (проверяется E2E)
- **SC-003**: Band score рассчитывается с точностью, соответствующей официальной конверсионной таблице IELTS (отклонение 0)
- **SC-004**: Страница симулятора загружается и готова к старту менее чем за 3 секунды на стандартном интернет-соединении
- **SC-005**: CTA-блок занимает не менее 30% viewport на экране результатов; кнопка CTA визуально акцентная и кликабельна (проверяется визуально + E2E)
- **SC-006**: Администратор может полностью заменить контент теста (все пассажи и вопросы) менее чем за 30 минут
- **SC-007**: Симулятор корректно работает на экранах шириной от 375px (мобильные) до 2560px (широкоформатные мониторы)
